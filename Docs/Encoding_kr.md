# 방식 1 — RGB 정육면체 큐브 분할 (RGB Cube Binning)

**설계 아이디어**  
- 동일한 크기의 정육면체(subspace) 256개를 RGB 색공간 내에 배치  
- 각 정육면체의 최대 크기는 $36^3$이며, 하나의 byte 값이 하나의 정육면체에 1:1로 대응  

---

## Step 1 — 1축 분할 (중앙 정렬)

각 RGB 채널 [0, 255]를 **7개의 bin**으로 중앙 정렬하여 분할  

```
전체 여백 = 256 - (7 × 36) = 4  →  양쪽 각 2씩 여백 부여
정렬 범위: [2, 253]

bin[0]: [  2,  37]
bin[1]: [ 38,  73]
bin[2]: [ 74, 109]
bin[3]: [110, 145]   ← 중앙 (인덱스 3)
bin[4]: [146, 181]
bin[5]: [182, 217]
bin[6]: [218, 253]
```

> [0, 1] 및 [254, 255]는 **의도적 여백**으로, 어떠한 bin에도 포함되지 않음  

---

## Step 2 — 3D 격자 생성

$R \times G \times B$ 축에 대해 데카르트 곱을 수행하여 $7^3 = 343$개의 Cube를 생성  
각 Cube는 `bin_idx = (r_idx, g_idx, b_idx)` 로 인덱싱  

---

## Step 3 — 제외 규칙 적용 (343 → 256)

**규칙 1 — 경계 제외 (Boundary Exclusion)**  
3개 축 중 **2개 이상**이 경계 인덱스 $\in \{0,\ 6\}$에 해당하면 해당 Cube를 제외  

```
예) (0,0,*), (0,6,*), (6,0,*), (6,6,*), ...  →  68개 제외
```

**규칙 2 — 중앙 제외 (Center Exclusion)**  
3개 축 중 **2개 이상**이 중앙 인덱스 $= 3$에 해당하면 해당 Cube를 제외  

```
예) (3,3,*), (3,*,3), (*,3,3)  →  19개 제외
```

| 구분 | 개수 |
|---|---|
| 3D 격자 전체 | 343 |
| 규칙 1 제외 | −68 |
| 규칙 2 제외 | −19 |
| **유효 bin** | **= 256** |

> 두 규칙의 중복 적용 = 0 (경계 인덱스 ≠ 중앙 인덱스이므로 교집합 없음).

---

## Step 4 — Byte → Bin 할당

남은 256개의 Cube에 **열거 순서대로 byte 값 `0x00`–`0xFF`를 순차 할당**  

```
byte 0x00 → bin_idx=(0,1,1)  R:[  2, 37]  G:[ 38, 73]  B:[ 38, 73]
byte 0x01 → bin_idx=(0,1,2)  R:[  2, 37]  G:[ 38, 73]  B:[ 74,109]
byte 0x7F → bin_idx=(3,2,6)  R:[110,145]  G:[ 74,109]  B:[218,253]
byte 0xFF → bin_idx=(6,5,5)  R:[218,253]  G:[182,217]  B:[182,217]
```

---

## Step 5 — 인코딩 / 디코딩

**인코딩 (Encoding)**
```
byte  →  encoding_map[byte]  →  (R 범위, G 범위, B 범위)
                              →  random.randint()으로 범위 내 좌표 무작위 선택
                              →  RGB(r, g, b)
```

**디코딩 (Decoding)**
```
RGB(r,g,b)  →  encoding_map 순회
            →  R/G/B 값이 모두 포함되는 bin 탐색
               (포함 판정: start ≤ value ≤ end, 양 끝 포함)
            →  해당 key 반환  (= 원본 byte 값)
```

> 동일한 byte라도 인코딩할 때마다 **서로 다른 RGB 좌표**가 생성될 수 있다 (seed로 재현 가능).  
> 디코딩은 **bin 소속 여부만 판별**하므로, 해당 bin 내의 어떤 RGB 좌표든 원본 byte를 유일하게 복원할 수 있음

---

## 예시

| 설계 선택 | 근거 |
|---|---|
| [0,1] 및 [254,255] 여백 제외 | 경계 노이즈에 대한 완충 구간 확보 |
| 규칙 1 — 경계 축 2개 이상 bin 제외 | 극단적 색상 조합 회피 |
| 규칙 2 — 중앙 축 2개 이상 bin 제외 | 회색 계열 밀집 구간 회피 |
| Bin 폭 = 36 | $7 \times 36 = 252 \leq 256$을 만족하는 최대 폭 |
| 최종 256개 bin | byte 값 0–255와의 **1:1 대응** 보장 |

# 방식 2 — RGB 직육면체 빈 분할 (RGB Cuboid Binning)

**요구 사항**
- RGB Color Model 전체 공간을 사용할 것  
$\because$ 일부 공간만 사용한 인코딩 방식인 RGB 정육면체 분할의 경우, Decoding이 실패하는 경우 발생

**설계 의도**  
- R, G 채널을 8등분, B 채널을 4등분하여 총 256개의 Encoding Cuboid를 확보  
- 0x00~0xff까지의 값을 각 Encoding Cuboid에 할당하여


## Step 1 — 1축 분할

R, G 축을 각각 8개의 bin으로 분할  
B 축을 4개의 bin으로 분할

## Step 2 — Byte 분할
**Encoding**  
각 byte를 8개의 bit로 분할  
$b_7, b_6, b_5, b_4, b_3, b_2, b_1, b_0$

상위 2 bit를 B, 중위 3 bit를 G, 하위 3 bit를 R 채널의 Index로 사용

# 방식 3 - 격자 변환

**요구 사항**  
- Diffusion Model을 이용해서 학습/추론 파이프라인을 통과해도 원본 바이트를 유지할 수 있을 것    
- 사람이 원본 데이터와 생성 데이터를 보고 유사성을 파악할 수 있을 것  

**설계 의도**  
- 2진수를 사용하여 각 숫자를 
- 0~9까지의 총 10개의 숫자를 사람이 구분하기 쉬운 이미지로 변환  





## Step 1 - 희소 행렬 이미지 생성
$28 \times 28$ 크기의 이미지를 4분할
좌상단, 우상단, 좌하단, 우하단 순으로 1, 2, 4, 8의 인덱스 설정  
해당 인덱스 값을 기반으로 0 ~ 9 정수 값 할당  

**할당 예시**
```
0 → 좌상단
5 → 좌상단, 좌하단
9 → 좌상단, 우하단
```
